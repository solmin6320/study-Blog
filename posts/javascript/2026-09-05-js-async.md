비동기를 "나중에 실행되는 코드"로만 외우면 항상 같은 자리에서 막힌다. **언제 실행되는지**를 결정하는 규칙, 즉 이벤트 루프를 먼저 잡아야 한다.

> 비동기는 "여러 개를 동시에 실행하는 것"이 아니다. **기다리는 동안 다른 일을 하는 것**이다. 스레드는 끝까지 하나뿐이고, 바뀌는 것은 실행 순서지 실행 개수가 아니다.

## 한 줄로 도는 언어

자바스크립트의 실행 스레드는 하나다. 그래서 `while` 무한 루프 하나로 화면 전체가 얼어붙는다. 대신 오래 걸리는 일(네트워크, 타이머, 파일)은 브라우저가 대신 맡고, 끝나면 **큐에 콜백을 넣어** 돌려준다.

### 매크로태스크와 마이크로태스크

- **매크로태스크**: `setTimeout`, `setInterval`, 이벤트 핸들러, 렌더링
- **마이크로태스크**: `Promise.then`, `queueMicrotask`, `await` 이후 코드

규칙은 간단하다. 콜스택이 비면 **마이크로태스크를 전부 비운 뒤** 매크로태스크를 하나 꺼낸다.

```js
console.log('1 동기');

setTimeout(() => console.log('4 타이머'), 0);

Promise.resolve()
  .then(() => console.log('3 마이크로태스크'));

console.log('2 동기');

// 1 동기 → 2 동기 → 3 마이크로태스크 → 4 타이머
```

`setTimeout(fn, 0)`이 즉시 실행이 아닌 이유가 여기 있다. 0ms는 "지금"이 아니라 "다음 매크로태스크 차례에"라는 뜻이다.

## Promise의 세 가지 상태

1. `pending` — 아직 결정되지 않음
2. `fulfilled` — 값으로 결정됨
3. `rejected` — 이유와 함께 실패

한 번 결정되면 **되돌아가지 않는다**. 그래서 `then`을 나중에 붙여도 이미 끝난 Promise의 결과를 받을 수 있다.

### async / await는 문법 설탕이다

```js
async function load(id) {
  const res = await fetch(`/posts/${id}.md`);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.text();
}
```

`await`는 함수를 "멈추는" 것처럼 보이지만 실제로는 **거기서 함수를 반으로 쪼개고**, 나머지 절반을 마이크로태스크로 등록한다. 그래서 `await` 아래 코드는 항상 현재 동기 코드가 전부 끝난 뒤에 실행된다.

## 병렬로 할 일을 직렬로 하지 말 것

가장 흔한 성능 실수다.

```js
// 느리다 — 두 요청이 순서대로 기다린다 (300ms + 300ms)
const index = await fetchIndex();
const post = await fetchPost(id);

// 빠르다 — 동시에 출발시킨 뒤 함께 기다린다 (300ms)
const [index, post] = await Promise.all([fetchIndex(), fetchPost(id)]);
```

서로 의존하지 않는 요청이라면 `Promise.all`이 기본값이어야 한다. 다만 하나라도 실패하면 전체가 실패한다는 점은 알고 써야 한다.

### 조합 함수 고르기

- `Promise.all` — 전부 성공해야 의미 있을 때. 하나 실패 시 즉시 reject.
- `Promise.allSettled` — 일부 실패를 감수하고 결과를 모두 보고 싶을 때.
  - 각 항목은 `{ status, value }` 또는 `{ status, reason }` 형태로 돌아온다.
  - 대시보드처럼 "되는 것만이라도 보여 줘야 하는" 화면에 맞는다.
- `Promise.race` — 가장 먼저 끝난 하나. 타임아웃 구현에 쓴다.
- `Promise.any` — 가장 먼저 **성공한** 하나. 전부 실패하면 `AggregateError`.

## 실패를 다루는 자리

오류를 잡는 위치는 "복구할 수 있는 곳"이다. 아무 데서나 `catch`하면 원인만 지워지고 화면은 여전히 비어 있다.

### try / catch / finally

```js
async function loadPost(id) {
  try {
    const text = await fetchText(`posts/${id}.md`);
    return parse(text);
  } catch (err) {
    // 화면단이 분기할 수 있게 원인을 코드로 바꿔서 올린다
    if (err.name === 'AbortError') throw err;          // 취소는 오류가 아니다
    throw Object.assign(new Error('글을 불러오지 못했습니다'), {
      code: 'network',
      cause: err
    });
  } finally {
    hideSkeleton();   // 성공이든 실패든 스켈레톤은 반드시 걷는다
  }
}
```

### fetch는 404에서 실패하지 않는다

기억할 것 두 가지.

- `fetch`는 **404에서도 reject하지 않는다.** 네트워크 자체가 실패해야 reject다. `res.ok`를 직접 확인해야 한다.
- `async` 함수 안에서 던진 오류는 그 함수가 돌려준 Promise의 rejection이 된다. 호출부에서 `await`하거나 `.catch()`를 붙이지 않으면 조용히 사라진다.

## 취소: AbortController

검색어를 칠 때마다 요청을 보내면, 늦게 도착한 옛 응답이 최신 결과를 덮어쓰는 일이 생긴다.

```js
let inflight = null;

async function search(query) {
  if (inflight) inflight.abort();      // 이전 요청 취소
  inflight = new AbortController();

  try {
    const res = await fetch(`/api/search?q=${encodeURIComponent(query)}`, {
      signal: inflight.signal
    });
    return await res.json();
  } catch (err) {
    if (err.name === 'AbortError') return null;   // 정상적인 흐름이다
    throw err;
  }
}
```

### debounce와 함께 쓴다

- `debounce` — 타이핑이 멈출 때까지 **요청을 보내지 않는다**. 요청 수 자체를 줄인다.
- `AbortController` — 이미 보낸 요청 중 **쓸모없어진 것을 끊는다**. 순서 역전을 막는다.

둘은 대체재가 아니라 짝이다. 입력이 잦은 화면이라면 보통 같이 쓴다.

## 정리

| 상황 | 선택 |
|---|---|
| 독립된 요청 여러 개 | `Promise.all` |
| 일부 실패 허용 | `Promise.allSettled` |
| 타임아웃 | `Promise.race` |
| 최신 입력만 유효 | `AbortController` + debounce |
| 순서가 중요한 작업 | `for...of` 안에서 `await` |

마지막 줄만 덧붙이면, `forEach` 콜백 안의 `await`는 **기다려지지 않는다**. 순서대로 처리해야 한다면 `for...of`를 쓰고, 동시에 처리해야 한다면 `map`으로 Promise 배열을 만든 뒤 `Promise.all`로 묶는다.

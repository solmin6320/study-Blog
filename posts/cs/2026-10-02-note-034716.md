## 그래픽 카드

> GPU를 중심으로 VRAM, 전원 회로, 메모리 컨트롤러, 냉각 장치 등을 포함한 그래픽 처리용 하드웨어 장치

- GPU = 그래픽 연산을 중심으로 대량의 데이터를 병렬 처리하는 프로세서

---
## 역할

> 그래픽 연산 -> 병렬 연산 -> 화면 출력 -> CPU와 데이터 교환

-**그래픽 연산**-

3D 게임이나 영상에서 발생하는 다음과 같은 작업을 처리

- 정점 변환
- 행렬 연산
- 조명 계산
- 텍스처 처리
- 픽셀 계산
- 화면에 출력할 색상 계산

-**병렬 연산**-

GPU는 동일하거나 유사한 연산을 많은 데이터에 동시에 적용하는 구조에 강함

- Pixel 1 -> 연산
- Pixel 2 -> 연산
- Pixel 3 -> 연산
- Pixel 4 -> 연산
...

-**차이점**-
- CPU는 적은 수의 코어를 중심으로 **다양한 종류의 작업을 빠르게 처리하는 구조**
- GPU는 **많은 연산 유닛을 이용**해 대량의 데이터를 **동시에 처리하는 구조**

-**화면 출력**-

GPU에서 계산한 최종 이미지 데이터를 디스플레이 장치로 전달

> 게임 데이터 -> GPU 연산 -> Frame Buffer -> Display Output -> Monitor

-**CPU와 데이터 교환**-

CPU가 프로그램 전체 흐름과 게임 로직 등을 처리하고 GPU가 그래픽 연산을 담당

> CPU -> 렌더링 명령 및 데이터 전달 -> GPU -> 그래픽 연산 -> 결과 반환 또는 화면 출력

## 내부 구조

-**GPU Core / SM / CU**-

GPU에서 실제 병렬 연산을 수행하는 핵심 처리 구조

- NVIDIA GPU에서는 주로 SM 단위로 구성 
- AMD GPU에서는 CU등의 구조를 사용

> GPU -> 여러 SM / CU -> 여러 실행 유닛 -> 병렬 연산

하나의 GPU 안에 매우 많은 연산 유닛이 존재하며 대량의 데이터를 동시에 처리할 수 있도록 설계

-**CUDA Core / Stream Processor**-

GPU 내부에서 실제 계산을 수행하는 연산 유닛

- NVIDIA에서는 CUDA Core라는 이름을 사용 
- AMD에서는 Stream Processor라는 용어를 사용

정수 연산이나 부동소수점 연산 등 다양한 계산을 수행

- 데이터 A -> 연산
- 데이터 B -> 연산
- 데이터 C -> 연산
- 데이터 D -> 연산

-**Warp / Wavefront**-

GPU에서 여러 스레드를 묶어서 실행하는 단위

- NVIDIA GPU에서는 Warp라는 개념을 사용 
- AMD GPU에서는 Wavefront라는 개념을 사용

> 많은 Thread -> Warp / Wavefront로 그룹화 -> GPU 실행

-**VRAM**-

GPU가 그래픽 데이터를 빠르게 읽고 쓰기 위해 사용하는 전용 메모리

데이터를 저장

- 텍스처
- 프레임 버퍼
- 깊이 버퍼
- 메시 데이터
- 셰이더 관련 데이터
- 각종 그래픽 리소스

> SSD -> RAM -> VRAM -> GPU 연산

VRAM 용량이 부족하면 필요한 데이터를 반복적으로 전송해야 해서 성능에 영향을 줄 수 있음

-**GPU Cache**-

GPU 내부에서 자주 사용하는 데이터를 빠르게 접근하기 위한 캐시 계층

VRAM -> GPU Cache -> Register

- CPU 캐시와 똑같이 자주 사용하는 데이터를 가까운 위치에 두어 메모리 접근 비용을 줄이는 역할

-**Register**-

GPU의 각 실행 스레드가 계산에 사용하는 값을 저장하는 매우 빠른 저장 공간

> Register -> 연산 유닛 -> 연산 수행

-**Memory Controller**-

GPU가 VRAM에 접근할 수 있도록 메모리 요청과 데이터 이동을 제어하는 하드웨어

> GPU -> Memory Controller -> VRAM

- GPU 내부 연산 유닛이 필요한 데이터를 VRAM에서 읽거나 결과를 VRAM에 저장할 때 사용

-Texture Unit-

텍스처 데이터를 샘플링하고 필터링하는 역할을 담당

> Texture Data -> Texture Unit -> 필요한 색상 데이터 생성


## 그래픽 처리 흐름

> CPU -> 렌더링 명령 및 그래픽 데이터 준비 -> GPU로 전달 -> VRAM에 데이터 저장 -> GPU가 데이터 읽기 -> Cache / Register -> 병렬 연산 -> 렌더링 결과 생성 -> Frame Buffer -> Display Output -> 모니터

-게임 실행 예시-

`drawPlayer();`
`drawEnemy();`
`drawMap();`

- CPU가 게임 로직과 렌더링 명령을 준비

- CPU -> Draw Call 생성 -> GPU로 명령 전달

- GPU는 필요한 그래픽 데이터를 VRAM에서 가져옴

- GPU -> Cache 확인 -> 필요한 데이터 접근 -> VRAM

- 가져온 데이터는 GPU의 여러 실행 유닛에서 병렬 처리

> Vertex Data -> Vertex Processing -> Rasterization -> Pixel / Fragment Processing

## 총 정리 및 핵심 요약

> GPU를 중심으로 VRAM, 메모리 컨트롤러, 전원 회로, 냉각 장치, 출력 회로 등이 결합된 그래픽 처리 장치

- GPU = 대량의 데이터를 병렬로 처리하는 프로세서

- GPU / SM / CU = GPU 내부의 병렬 연산 처리 구조

- CUDA Core / Stream Processor = 실제 계산을 수행하는 연산 유닛

- Warp / Wavefront = 여러 스레드를 묶어 실행하는 단위

- Register = GPU 스레드가 사용하는 매우 빠른 저장 공간

- GPU Cache = GPU가 자주 사용하는 데이터를 빠르게 접근하기 위한 캐시

- VRAM = 그래픽 데이터를 저장하는 고속 메모리

- Memory Controller = GPU와 VRAM 사이의 데이터 이동을 제어

- Texture Unit = 텍스처 샘플링 및 필터링 처리


-**그래픽 처리**-

> CPU -> 렌더링 명령 준비 -> GPU -> VRAM / Cache -> 병렬 연산 -> Frame Buffer -> Display Output -> Monitor

-메모리 접근-

> GPU -> GPU Cache 확인 -> Cache Hit -> 데이터 사용

> GPU -> GPU Cache Miss -> Memory Controller -> VRAM -> 데이터 획득

-**CPU와 차이점**-
- CPU = 복잡하고 다양한 작업을 순차적으로 빠르게 처리하는 데 강함

- GPU = 동일하거나 유사한 연산을 많은 데이터에 동시에 적용하는 병렬 처리에 강함

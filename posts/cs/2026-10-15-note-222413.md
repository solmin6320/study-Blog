## 네트워크

> 컴퓨터와 같은 장치들이 서로 데이터를 주고받을 수 있도록 연결하고 통신을 가능하게 하는 체계

- 통신 대상: 데이터를 보내고 받을 장치나 프로그램이 필요
- 주소와 전달 방법: 데이터가 어디로 가야 하는지, 다음 단계로 어떻게 전달할지 결정
- 통신 규칙: 데이터를 어떤 형식으로 보내며 받은 데이터를 어떻게 해석할지 결정

-**프로토콜**-

통신하는 장치나 프로그램이 데이터를 주고 받기 위해 따라야 하는 규칙

-구성 요소-

- Ethernet: 같은 네트워크 링크에서 프레임을 전달하는 데 사용
- IP: 네트워크 사이에서 데이터그램을 전달하는데 사용
- TCP: 연결 기반의 신뢰성 있고 순서가 보장된 바이트 스트림 제공
- UDP: 데이터그램 방식의 전송 서비스 제공
- DNS: 도메인 이름 등과 관련된 정보를 조회
- HTTP: 웹 요청과 응답의 의미 및 형식을 정의
- TLS: 데이터 기밀성 및 무결성을 제공하도록 통신을 보호

-**네트워크 계층**-

네트워크 통신에 필요한 여러 기능들이 역할별로 나누어 구성된 계층 구조

-OSI 7계층-

| 계층 | 이름 | 핵심 역할|
| --- | --- | --- |
| 7계층 | 응용 | 애플리케이션 수준의 네트워크 서비스 |
| 6계층 | 표현 | 데이터 표현과 변환에 관한 기능 |
| 5계층 | 세션 | 통신 세션과 관련된 기능 |
| 4계층 | 전송 | 애플리케이션 간 데이터 전달 |
| 3계층 | 네트워크 | 네트워크 간 패킷 전달 |
| 2계층 | 데이터 링크 | 링크 내부에서 프레임 전달 |
| 1게층 | 물리 | 신호를 물리적 매체로 전달 |

-TCP/IP 계층-

| TCP/IP 계층 | 프로토콜|
| --- | --- |
| 응용 계층 | HTTP, DNS 등 |
| 전송 계층 | TCP, UDP |
| 인터넷 계층 | IP |
| 링크 계층 | Ethernet

## 역할

-**서로 다른 장치 사이에 데이터 전달**-

-브라우저가 백엔드 서버에 요청을 보냄-

TCP/IP 계층 기준(TCP 사용)
- HTTP는 어떤 리소스를 요청하는지 표현
- TCP가 연결과 순서가 보장된 바이트 스트림의 전달을 지원
- IP가 네트워크 사이에서 데이터그램을 전달
- 네트워크 링크에서 데이터를 전달하는 데 사용(링크 계층)


이 기능들은 서로 대체 관계가 아닌 **협력 관계라는 것이 중요**

-**보안 경계와 장애 지점을 구분**-

| 발생한 현상 | 확인할 수 있는 영역|
| --- | --- |
| 도메인으로 서버에 접근 불가 | DNS, 주소 설정, 라우팅 |
| 서버에 연결할 수 없음 | 포트, 방화벽 |
| HTTPS 연결 단계에서 실패 | TLS 설정, 프로토콜 협상 |
| 서버가 401 반환 | 인증 관련 애플리케이션 처리 |
| 서버가 403 반환 | 접근 권한 정책 |
| 응답이 늦거나 타임아웃이 발생 | 네트워크 지연, 서버 부하 |

- 실제 원인을 로그와 연결 상태를 같이 보며 해결하는게 좋음

## 내부 구조

-**사용자 영역**-

> 애플리케이션 -> 소켓 API -> 운영체제 네트워크 기능

- 애플리케이션은 일반적으로 소켓 API 등을 사용

-**커널 영역**-

-네트워크 통신-
- 소켓 관리
- TCP / UDP 처리
- IP 패킷 처리
- 라우팅
- 네트워크 송수신 버퍼 관리
- 네트워크 장치 드라이버와의 상호작용

-**네트워크 인터페이스(NIC)**-

컴퓨터가 네트워크에 연결되어 송수신할 수 있도록 하는 하드웨어 장치

- Ethernet
- Wi-Fi

> 애플리케이션 -> OS 커널 -> 네트워크 드라이버 -> NIC -> 네트워크

-**Socket(소켓)**-

애플리케이션이 네트워크 통신을 수행하기 위해 사용하는 인터페이스

-Spring Boot가 Redis에 요청을 보내는 경우를 가정-
> Spring Boot -> 소켓 API -> OS  네트워크 처리 -> Redis 서버

- 소켓 자체가 메모리 버퍼를 의미하는 것은 아님

-**Buffer**-

데이터를 일시적으로 보관하는 메모리 공간

- 송신 버퍼
- 수신 버퍼
- 애플리케이션에서 사용하는 데이터 버퍼

> 애플리케이션 데이터 -> 송신 처리 -> 네트워크 전송 -> 네트워크 수신 -> 수신 처리 -> 애플리케이션에서 데이터 읽기

## 전체 흐름

-브라우저에서 서버로 HTTPS 요청을 보내는 상황-

> 브라우저 -> DNS 및 연결 준비 -> OS 네트워크 처리 -> NIC -> 네트워크 -> 서버 NIC -> 서버 OS -> Spring Boot

1. 요청 생성
2. 통신 대상 확인
3. 연결 및 데이터 전송 준비
4. 네트워크 데이터 처리
5. 네트워크 전달
6. 서버에서 데이터 수신
7. 애플리케이션 처리 및 응답
---
## 총 정리 및 핵심 요약

- NIC = 네트워크 데이터 송수신을 담당하는 인터페이스 장치
- Socket = 애플리케이션이 네트워크 통신 기능을 이용하기 위한 인터페이스
- Buffer = 전송하거나 수신한 데이터를 일시적으로 보관하는 공간

-실제 통신 흐름-

> 애플리케이션 -> 소켓 API -> OS 네트워크 처리 -> NIC -> 네트워크 -> 수신 측 OS -> 수신 애플리케이션

- 네트워크 통신은 애플리케이션이 만든 데이터가 네트워크 처리 기능, 네트워크 인터페이스 및 여러 장비를 거쳐 상대방 애플리케이션에 전달되는 과정을 의미

## CPU

> 프로그램의 명령어를 가져오고(fetch), 해석하고(decode), 실제 연산을 수행하고(execute), 그 결과를 반영하는 범용 프로세서

CPU = 프로그램의 명령을 실행하는 핵심 처리 장치

---

## 역할

> 명령어 실행 -> 연산 -> 프로그램 흐름 제어 -> 메모리와 연결

-**명령어 실행**-

`int result = a + b;`

- 코드가 실행되면 CPU가 실행할 수 있는 기계어 명령어들로 변환되어 CPU에서 처리됨

-**연산**-

- 정수 연산, 논리 연산, 비교, 주소 계산, 분기 등 여러 종류의 연산을 수행

-**프로그램 흐름 제어**- 
```java
if (a > 10) {
    . . .
}
```

- 조건에 따라 다른 코드를 실행해야 함

-**메모리 연결-**

- CPU가 프로그램을 실행하려면 데이터를 가져와야 함
- CPU에는 캐시 계층이 존재하고 시스템 메모리(RAM), 저장장치 등과 연결되어 데이터를 주고 받음

---

## 내부 구조
-**Core**-


실제 명령어를 실행하는 CPU 내부의 독립적인 처리 단위

> 4 Core CPU -> Core 0, Core 1, Core 2, Core 3

- 여러 코어가 있으며 CPU는 여러 실행 흐름을 동시에 처리할 수 있음

- Core 수 != 동시에 실행되는 프로그램 수

- 운영체제의 스케줄링과 하드웨어의 SMT/Hyper-Threadling 같은 구조까지 관련되기 때문

-**Register**-

CPU 코어 안에 존재하는 현재 사용하는 값을 보관하기 위한 매우 빠른 저장 공간  

> RAM -> Cache -> Register -> 연산

- 레지스터에는 일반 데이터뿐만이 아닌 프로그램 카운터(PC),  상태 정보 등도 포함됨

-**Cache**-

자주 사용할 가능성이 높은 데이터를 CPU 가까이에 미리 두어 메모리 접근 시간을 줄이는 것

- CPU는 RAM에 있는 데이터를 매번 가져오면 CPU의 처리 속도에 비해 메모리 접근이 병목이 될 수 있으므로 캐시가 존재함

> RAM -> L3 Cache -> L2 Cache -> L1 Cache -> Register

-**Execution Unit / ALU**-

CPU 내부에 존재하며 실제 산술 및 논리 연산을 수행하는 실행 유닛

`5 + 3`

`5 > 3`

`a AND b`


- 현대 CPU는 ALU 하나만 존재하는 단순 구조가 아닌 여러 종류의 실행 유닛을 가지고 있음

 -**Branch Predictor**-

CPU가 다음에 실행될 코드 위치를 미리 예측하는 하드웨어

```java
If (condition) {
    A
} else {
    B
}
```

- CPU가 실제 조건 결과를 기다리지 않고 어느 쪽이 실행될 가능성이 높은지 예측해서 먼저 실행할 수 있음
- 틀리면 잘못 추측해서 실행한 명령어를 폐기하고 올바른 경로를 다시 진행함


-**TLB**-

최근 사용한 가상 주소 -> 물리 주소 변환 정보를 저장하는 캐시


> 일반 캐시(L1, L2, L3)

- 데이터/ 명령어를 찾기 위한 캐시

> TLB

- 주소 변환 결과를 빠르게 찾기 위한 캐시

—--

## 전체 흐름

실행 흐름

> 프로그램 -> 명령어 Fetch -> Decode -> 필요한 데이터 확인 -> Register / Cache -> Execution Unit -> 연산 수행 -> 결과 저장 -> 다음 명령


- TLB에서 Hit 났을 때

> CPU instruction -> Virtual Address 생성 -> TLB -> Hit -> 물리 주소

- TLB에서 Miss 났을 때

> CPU instruction -> Virtual Address 생성 -> TLB -> Miss -> Page Table 확인 -> 물리주소 획득 -> Cache -> RAM

즉 캐시가 **데이터를 빠르게 찾는 구조**

---
## 총 정리 및 핵심 요약

CPU = 프로그램의 명령어를 실행하는 핵심 처리 장치

- Core = 명령어를 실행하는 처리 단위
- Register = CPU가 즉시 사용하는 값을 저장
- Cache = 자주 사용하는 데이터/명령어를 CPU 가까이에 저장
- Execution Unit / ALU = 실제 연산 수행
- Branch Predictor = 다음 실행 경로 예측
- TLB = 가상 주소 → 물리 주소 변환 결과를 캐싱

-**메모리 접근**-

> 가상 주소 → TLB에서 주소 변환 확인 → 물리 주소 획득 → Cache 확인 → 필요하면 RAM 접근

Flexbox는 **한 줄**을 다루고 Grid는 **면**을 다룬다. 이 한 문장을 기억하면 어떤 걸 써야 할지 고민하는 시간이 절반으로 준다. 카드 목록처럼 행과 열이 동시에 의미를 갖는 레이아웃은 Grid가 맞다.

## 최소한의 문법

```css
.board {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 24px;
}
```

`1fr`은 "남은 공간을 1만큼 가져간다"는 뜻이다. `%`와 달리 `gap`을 계산에 넣어 주기 때문에 `calc(33.333% - 16px)` 같은 식을 직접 쓸 일이 없다.

### fr과 auto와 minmax

| 값 | 뜻 | 쓰는 곳 |
|---|---|---|
| `auto` | 콘텐츠 크기만큼 | 사이드바, 아이콘 열 |
| `1fr` | 남은 공간을 비율로 | 본문 열 |
| `minmax(200px, 1fr)` | 최소 200px, 남으면 늘어남 | 카드 트랙 |
| `min-content` | 더 못 줄이는 최소 | 줄바꿈을 막을 때 |
| `max-content` | 줄바꿈 없는 최대 | 표 머리글 |

`1fr`의 기본 최소값이 `auto`라는 점이 함정이다. 긴 단어나 코드블록이 들어가면 트랙이 콘텐츠 최소 너비 아래로 못 줄어서 그리드가 통째로 넘친다. 그래서 실무에서는 거의 항상 이렇게 쓴다.

```css
.layout {
  display: grid;
  /* 0을 명시해 트랙이 콘텐츠보다 작아질 수 있게 허용한다. */
  grid-template-columns: minmax(0, 1fr) 280px;
}
```

## 미디어쿼리 없이 반응형

카드 목록에서 제일 많이 쓰는 한 줄이다.

```css
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(min(280px, 100%), 1fr));
  gap: 32px 24px;
}
```

읽는 순서는 이렇다.

1. `auto-fill` — 컨테이너 폭이 허락하는 만큼 트랙을 만든다.
2. `minmax(280px, 1fr)` — 각 트랙은 280px 아래로 줄지 않고, 남는 공간은 나눠 갖는다.
3. `min(280px, 100%)` — 화면이 280px보다 좁을 때 트랙이 컨테이너를 넘지 않게 묶는다. 360px 기기에서 가로 스크롤이 생기는 사고는 대부분 이 `min()`을 빼서 발생한다.

### auto-fill과 auto-fit의 차이

- `auto-fill`은 빈 트랙을 **남겨 둔다**. 아이템이 2개여도 3열 자리가 유지된다.
- `auto-fit`은 빈 트랙을 **접는다**. 아이템 2개가 화면 전체로 늘어난다.

카드가 몇 개 없을 때 거대하게 부푸는 게 싫다면 `auto-fill`이 정답이다.

## 배치: 선을 센다

Grid의 좌표는 칸이 아니라 **선**이다. 3열이면 선은 4개고, 끝 선은 `-1`로도 부를 수 있다.

```css
.toolbar .search { grid-column: 1; }
.toolbar .select { grid-column: 2; }
.toolbar .chips  { grid-column: 1 / -1; }  /* 전체 폭 */
```

여기서 놓치기 쉬운 규칙 하나. **자동 배치는 DOM 순서를 따른다.** 위 코드에서 `.chips`를 `.select`보다 앞에 두면, 전체 폭을 먹은 `.chips`가 2행을 차지하고 커서가 되돌아갈 수 없어서 `.select`가 3행으로 밀린다. 열만 지정하고 행을 비워 둘 때는 마크업 순서까지 같이 설계해야 한다.

### 이름 붙인 영역

복잡해지면 `grid-template-areas`가 읽기 쉽다.

```css
.post-body {
  display: grid;
  grid-template-columns: minmax(0, 1fr) 240px;
  grid-template-areas: "prose toc";
  gap: 40px;
}
.prose { grid-area: prose; }
.toc   { grid-area: toc; }

@media (max-width: 1023px) {
  .post-body {
    grid-template-columns: minmax(0, 1fr);
    grid-template-areas: "toc" "prose";   /* 좁으면 목차를 위로 */
  }
}
```

## 자주 밟는 지뢰

- `gap`은 트랙 **사이**에만 생긴다. 바깥 여백은 `padding`으로 따로 준다.
- `align-items: start`를 주지 않으면 모든 카드가 행에서 가장 큰 카드 높이로 늘어난다. 메모지처럼 높이가 제각각이어야 하는 디자인에서는 필수다.
- `justify-content`는 **트랙 전체**를, `justify-items`는 **각 칸 안의 내용**을 정렬한다. 이름이 비슷해서 매번 헷갈린다.
- 그리드 아이템에 `float`이나 `vertical-align`은 무시된다. 안 먹는다고 시간을 버리지 말자.

## 언제 Flex를 쓸까

- 요소가 한 줄에 나란히, 개수가 유동적이고, 서로 간격만 맞으면 될 때 → Flex
- 행과 열 위치가 의미를 가질 때, 겹치거나 영역을 건너뛸 때 → Grid

둘 다 쓰는 게 정상이다. 페이지 골격은 Grid로, 버튼 묶음 같은 작은 덩어리는 Flex로 잡으면 대체로 깔끔하게 끝난다.

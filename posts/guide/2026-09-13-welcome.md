공부한 내용을 **메모지처럼 붙여 두는 곳**이다. 완성된 글만 올리는 공간이 아니라, 반쯤 이해한 것도 일단 붙여 두고 나중에 고쳐 쓰는 작업대에 가깝다. 이 메모는 그 작업대를 어떻게 쓰는지 정리한 것이다.

> 기록의 목적은 자랑이 아니라 **다시 찾아보기**다. 그래서 검색·태그·수정 날짜가 화면의 중심에 있다.

## 화면은 세 장뿐이다

| 화면 | 파일 | 하는 일 |
|---|---|---|
| 메모 보드 | `index.html` | 전체 목록, 검색, 태그 필터, 정렬 |
| 글 상세 | `post.html?id=...` | 본문 렌더, 목차, 이전/다음 글 |
| 에디터 | `write.html` | 작성, 미리보기, 파일로 내보내기 |

목록 화면은 본문을 읽지 않는다. `posts/index.json`과 `posts/categories.json` 두 개만 받아서 그린다. 글이 백 개가 되어도 첫 화면 속도가 그대로인 이유다. 본문 파일은 상세 화면에 들어갈 때 그 글 하나만 받아 온다.

## 글 하나 = 파일 하나

글 한 편은 `.md` 파일 하나다. 데이터베이스도, 서버도 없다. 파일은 **카테고리 폴더 안에** 들어간다.

```text
posts/
  categories.json          카테고리 정의 (직접 열어 고쳐도 된다)
  index.json               전체 목록
  guide/2026-09-13-welcome.md
  css/2026-09-10-css-grid.md
  javascript/2026-09-05-js-async.md
```

폴더로 나눠 두면 글이 쌓여도 파일 탐색기에서 바로 찾아 고칠 수 있다. 파일 맨 위에는 이런 머리말이 붙는다.

```yaml
---
id: 2026-09-13-welcome
title: 이 블로그 사용법
created: 2026-09-13T10:20:00+09:00
updated: 2026-09-13T16:40:00+09:00
tags: [안내, 마크다운]
category: guide
color: amber
pinned: true
---
```

여기서 규칙은 딱 세 가지다.

1. `id`와 **파일 이름이 같아야 한다**. `post.html?id=2026-09-13-welcome` 주소가 곧 `posts/guide/2026-09-13-welcome.md` 를 가리키기 때문이다.
2. `category`는 **폴더 이름과 같아야 한다**. 이 글의 `category: guide`는 곧 `posts/guide/` 폴더라는 뜻이다.
3. `created`는 한 번 정해지면 **절대 바꾸지 않는다**. 고칠 때 갱신하는 값은 `updated` 쪽이다.

두 값이 같으면 화면은 수정 표기를 아예 숨긴다. 같은 날짜를 두 번 보여 주는 것은 정보가 아니라 소음이기 때문이다.

## 쓰고 올리는 순서

- `write.html`을 연다. 작성 중 내용은 브라우저에 자동 임시저장된다.
  - 임시저장은 **백업이 아니다**. 다른 브라우저에서는 보이지 않는다.
  - 브라우저 데이터를 지우면 같이 사라진다.
- 다 썼으면 **파일로 내보내기**를 누른다. `.md` 파일과 새 `index.json`이 내려받아진다.
- `.md`는 `posts/<카테고리>/` 폴더에, `index.json`은 `posts/` 바로 아래에 넣고 커밋한다. 이때부터가 진짜 저장이다.
  - 새 카테고리를 만들었다면 폴더를 직접 만들고 `categories.json`도 함께 덮어쓴다.

체크리스트로 두면 빠뜨리지 않는다.

- [x] 제목과 요약 적기
- [x] 태그 2~3개 붙이기
- [ ] `.md`를 카테고리 폴더에, `index.json`을 `posts/`에 넣기
- [ ] 커밋하고 배포 확인하기

### 색은 분류가 아니라 표식이다

메모지 색은 `amber` `mint` `sky` `rose` `lilac` `lime` 여섯 가지다. 색으로 주제를 나누려 하면 금세 규칙을 잊는다. "오늘 기분"이나 "급한 것"처럼 가벼운 표식으로 쓰는 편이 오래간다. 분류는 `category`, 검색은 `tags`가 맡는다.

## 카테고리로 나누기

주제가 섞이면 나중에 못 찾는다. 그래서 글은 카테고리 폴더로 나눠 둔다. 목록은 `posts/categories.json` 한 파일이 정한다.

```json
{
  "categories": [
    { "slug": "css", "name": "CSS", "color": "sky", "description": "레이아웃 · 스타일 · 반응형", "order": 2 }
  ]
}
```

| 필드 | 뜻 |
|---|---|
| `slug` | **폴더 이름**. 영문 소문자·숫자·하이픈만. 한 번 정하면 바꾸지 않는다 |
| `name` | 화면에 보이는 이름. 한글로 써도 된다 |
| `color` | 그 분류의 기본 메모지 색 |
| `order` | 카테고리 줄에서의 순서 |

카테고리를 새로 만드는 방법은 두 가지다.

1. 에디터에서 **+ 새 카테고리**를 눌러 만든다. 내보낼 때 `categories.json`이 함께 내려온다.
2. `categories.json`을 직접 열어 한 줄 추가하고 `posts/` 아래에 같은 이름의 폴더를 만든다.

`slug`를 나중에 바꾸면 그 안의 글이 전부 길을 잃는다. 이름이 마음에 안 들면 `slug`는 두고 `name`만 고치면 된다. 글이 없는 카테고리도 카테고리 줄에 흐리게 남는다 — 비어 있다는 사실 자체가 "여기에 쓰면 된다"는 표시다.

## 찾기

보드 화면에서 `/` 키를 누르면 검색창으로 바로 간다. 카테고리는 하나만, 태그는 여러 개를 동시에 고를 수 있고 검색어까지 셋이 함께 걸린다. 이 상태는 모두 주소에 남는다. 즉 **지금 보고 있는 화면을 그대로 링크로 보낼 수 있고**, 뒤로가기를 누르면 직전 조건으로 정확히 돌아온다.

```text
index.html?cat=css&q=grid&tags=css,layout&sort=updated
```

## 잘 안 될 때

- 화면이 비어 있고 "로컬 서버로 열어 주세요"가 뜬다면 `.html` 파일을 더블클릭해서 연 것이다. 브라우저는 `file://` 에서 다른 파일 읽기를 막는다. `start.bat`으로 로컬 서버를 켜자.
- 목록에는 있는데 상세가 404라면 `.md` 파일 이름과 `id`가 어긋났거나, 파일이 `category`와 다른 폴더에 들어 있는 것이다.
- `categories.json`이 깨지면 화면이 멈추는 대신 글에 적힌 `category` 값으로 카테고리 줄을 대신 만든다. 표시 이름이 폴더명으로 보인다면 이 상태다.
- 머리말이 깨졌다면 목록 정보만으로 최대한 그려 주고 경고를 띄운다. 글이 통째로 사라지지는 않는다.

여기까지가 전부다. 나머지는 그냥 쓰면 된다.

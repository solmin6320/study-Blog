## Docker

> 애플리케이션을 개발, 전달, 실행하기 위한 플랫폼

**Docker가 없을 때**

개발자의 컴퓨터

> Java 21, Spring Boot, 환경변수, OS 설정, 라이브러리 버전 A

**서버 배포**

> Java 17, 라이브러리 버전 B

- 실행 환경이 다르기 때문에 실행 오류가 발생함

Docker는 애플리케이션과 사용자 공간 파일들을 **이미지** 형태로 패키징 하고 그 **이미지**를 기반으로 **컨테이너**를 실행
 
---
## 메모리 구조

> 도커 컨테이너는 기본적으로 **호스트 커널을 공유**하면서 프로세스에 격리된 실행 환경을 제공하는 방식

> Host OS -> Container Spring Boot - Container MariaDB

**namespace** - 도커 컨테이너 **격리**에 사용

PID namespace

 > Host - PID 100, PID 101, PID 102 . . .

> 컨테이너 - PID 1, PID 2, PID 3 . . .

컨테이너 내부 프로세스 관점에서는 자신의 프로세스 공간이 따로 있는것 처럼 보임

**cgroups** - 컨테이너 리소스 제한

`docker run --memory=1g --cpus=2 my-app`

> Host -> Container A - CPU, Memory 제한 | Container B - CPU, Memory 제한


--memory=1g - 이 Container의 프로세스들이 사용할 수 있는 메모리 상한을 1GB로 제한

## 역할

> Build -> Package -> Ship -> Run

**백엔드 관점**

> Spring Boot -> Docker Image -> Docker Registry -> 다른 서버 -> Docker Container -> Spring Boot 실행

---
## Docker Engine

> Docker CLI -> Docker API -> Docker Daemon (dockerd)

 - Image - Container를 만들기 위한 **읽기 전용 템플릿**

> Spring Boot Image - Java, Spring Boot, 설정, 라이브러리

- Container - Image를 기반으로 만들어진 **실행 가능한 인스턴스**
- 하나의 Image에서 여러 Container를 만들 수 있음

## 코드

```java
@SpringBootApplication
@RestController
public class DemoApplication {
  
  public static void main(String[] args) {
    SpringApplication.run(DemoApplication.class, args);
  }
  
  @GetMapping("/docker")
  public String Docker() {
    return "docker";
  }
}
```
- 8080 포트에서 Spring Boot 서버가 실행

- Dockerfile

```dockerfile
FROM eclipse-temurin:21-jre

WORKDIR /app

COPY target/demo-0.0.1-SNAPSHOT.jar app.jar

EXPOSE 8080

ENTRYPOINT ["java", "-jar", "app.jar"]
```

`FROM eclipse-temurin:21-jre`
- Java Runtime이 준비된 기반 Image를 사용함

`WORKDIR /app`
- Container 내부 작업 디렉터리를 **/app** 으로 지정

`COPY target/demo-0.0.1-SNAPSHOT.jar app.jar`
- Spring Boot JAR을 내부로 복사(Maven 기준)

`EXPOSE 8080`
- 애플리케이션이 사용하는 포트를 Image 메타데이터로 표현

주의할점: EXPOSE가 실제로 윈도우나 리눅스 호스트의 포트를 외부에 자동 공개하는 것은 아 

`ENTRYPOINT ["java", "-jar", "app.jar"]`
- Container가 시작될 때 실행할 프로세스를 지정

## 전체 흐름

`docker run -p 8080:8080 spring-demo`

- Docker CLI 실행
> Terminal -> docker CLI -> docker API -> dockerd

- dockerd가 Image 확인
> Local Image - 있음 -> 사용 | 없음 -> Registry -> Image Pull

- Container 생성
> Image -> Container 생성

- 파일시스템 구성
> Image -> Layer 1 - Layer 2 - Layer 3

- 격리 환경 구성
> Container Process -> PID Namespace - Network Namespace - Mount Namespace . . . | cgroup -> CPU - Memory - Process 수 . . .

- Conatiner Runtime
> docker CLI -> dockerd -> containerd -> runc -> Kernel -> Spring Boot process

--- 
## 핵심 정리 및 배운점

**Docker**
> 애플리케이션을 패키징 -> Image | Image를 실행 -> Container | Container를 관리 Docker Engine

**내부 구조**
> docker CLI -> Docker API -> dockerd -> containerd -> runc -> Kernel -> Container Process -> Spring Boot

- Container - 호스트의 커널 기능을 이용해서 프로세스를 격리한 실행 환경
- Image - 실행을 위한 읽기 전용 템플릿

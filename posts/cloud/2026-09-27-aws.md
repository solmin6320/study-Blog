## AWS(Amazon Web Servcie)
> 서버, 스토리지, 데이터베이스, 네트워크, 보안, 모니터링 등의 IT 인프라를 인터넷을 통해 서비스 형태로 사용할 수 있게 제공하는 플랫폼
---
## 전체 구조

AWS 자체가 내 PC에서 실행되는 프로그램은 아님

AWS는 전 세계에 존재하는 **물리적인 데이터센터**와 **네트워크 인프라 위에서 동작**하는 **거대한 분산 시스템**

> AWS -> 여러 Region - 각 Region의 여러AZ - 데이터센터 - 물리 서버 - 네트워크 장비 - 스토리지 시스템 - 이를 관리하는 소프트웨어

- Region
- AWS가 **물리적으로 인프라를 배치**한 하나의 지리적 영역

> AWS -> 서울 Region - 도쿄 Region - 싱가포르 Region . . . 

- Availability Zone(AZ)
- Region 하나를 다시 여러 개의 **격리된 인프라 영역**으로 나눈 것

> 서울 Region -> AZ A - AZ B - AZ C - AZ D . . .

- Control Plane
- 리소스를 만들고, 수정하고, 삭제하고, 설정을 관리하는 영역

> EC2 생성, EC2 삭제, VPC 생성, Security Group 변경, RDS 설정 변경 . . .

즉 **인프라를 어떻게 만들고 관리할 것인가**를 담당

- Data Plan
- 만들어진 리소스가 **서비스를 제공하면서 실제 데이터를 처리하는 영역**

> 사용자 요청 -> EC2 -> Spring Boot

즉 만들어진 **리소스가 실제 업무를 어떻게 수행할 것인가**를 담당

---
## 역할

-**인프라 제공**-

서버 - EC2

DB - RDS(관계형 DB)

파일 저장 - S3

네트워크 - VPC

-**인프라 추상화**-
> CPU, RAM, 메인보드, 전원, 네트워크 장비, 냉각 . . .

AWS가 물리 인프라를 관리하고 사용자는 API/콘솔 등을 통해 추상화된 리소스를 사용

-**글로벌 인프라 제공**-

- 서울 Region
- Tokyo Region

더 넓은 글로벌 서비스에서는 여러 Region에 애플리케이션을 배포하는 설계도 가능

---
## 전체 흐름

> EC2 생성 -> AWS API / Comtrol Plane -> AWS 인프라에서 실제 리소스 생성 -> EC2 내부에서 OS 실행
---

## 관리 흐름
> 개발자 -> Console / CLI / SDK -> AWS API
-> Control Plane -> AWS Resource 생성/변경

**인프라를 만드는 흐름**

---
## 실제 서비스 흐름

>사용자 -> Internet -> AWS Network -> ALB -> EC2 -> Spring Boot -> RDS

**만들어진 인프라가 실제 요청을 처리하는 흐름**

---
## 핵심 정리 및 배운점

AWS - Amazon이 제공하는 클라우드 플랫폼

> 물리 데이터센터 -> 물리 하드웨어 -> AWS 관리/가상화 계층 -> 논리적 AWS 리소스 -> EC2 / VPC / S3 . . .

Cotrol Plane - 리소스를 만들고 관리하는 영역

Data Plane - 만들어진 리소스가 실제 요청과 데이터를 처리하는 영역

## DI(Dependency Injection)
> 객체가 자신이 필요로 하는 의존 객체를 직접 생성하거나 찾지 않고 외부에서 필요한 객체를 전달받도록 하는 방

Ioc - 객체 생성 / 구성의 제어권을 외부로 넘김

DI - 그 외부에서 필요한 의존 객체를 실제로 전달

---
## 메모리 내부
DI 자체는 Heap에 존재하는 객체가 아님

DI -> 설계 방식 / 동작 원리

```java
private final UserRepository userRepository;
```

> JVM Process -> ApplicationContext - userRepository - userService 객체 -> repository -> userRepository 객체

DI의 메모리 관점
- Container가 이미 생성했거나 생성할 Dependency 객체의 참조를 **의존 객체의 생성자**, **메서드, 필드** 등에 전달하여 **객체 간 연결을 구성하는 것**

---
## 역할

객체가 자신의 의존 객체를 직접 생성하거나 찾는 책임을 제거하는 것

```java
public interface UserRepository {
  void save();
}
```

```java
public class JpauserRepository implements UserRepository {
  
  @Override
  public void save() {
    
  }
}
```

```java
public class UserService {
  
  private final UserRepository userRepository;
  
  public UserService(UserRepository userRepository) {
    this.userRepository = userRepository;
  }
}
```
이 코드에서 `userService`는 `JpaUserRepository`를 직접 생성할 필요가 없고
`userRepository`라는 의존성이 필요한 것만 알고 있음

- 구현체를 바꾸거나 테스트용 객체를 주입하기가 쉬워짐

DI 방식으로는 크게 생성자 DI 방식과 Setter DI 방식이 있고 일반적으로 생성자 주입 방식을 권장

---
## 코드
```java
@Repository
public class UserRepository {
  
  public void save() {
    System.out.println("사용자 저장");
  }
}
```

```java
@Service
public class UserService {
  
  private final UserRepository userRepository;
  
  public UserService(UserRepository userRepository) {
    this.userRepository = userRepository;
  }
  
  public void createUser() {
    userRepository.save();
  }
}
```

```java
@SpringBootApplcation 
  public class Application {
    
    public static void main(String[] args) {
      SpringApplication.run(Application.class, args);
    }
  }
```

이 코드에서 UserService는 직접 `new UserRepository`를 하지 않음

대신

> UserService -> 생성자 매개변수 -> userRepository 필요

선언하면 Spring Container가

> UserRepository Bean 생성 -> UserService 생성자 확인 -> UserRepository 필요 -> UserRepository Bean 전달 -> UserService 생성

---
## 전체 흐름

> OS -> JVM Process -> ApplicationContext 생성/초기화 -> Spring이 관리할 Bean 정보 구성 -> UserRepository Bean 등록, UserService Bean 등록 -> UserService 생성자 분석 -> UserRepository 필요 -> container에서 UserRepository Bean 탐색 -> 확보 후 UserService 생성자 호출 -> UserService 객체 생성 -> UserRepository 객체를 가리키는 참조 저장 -> DI 완료

## 핵심 흐름

> UserRepository 생성 -> UserRepository 객체 존재 -> UserService 생성 필요 -> UserService 생성자에 UserRepository 전달 -> UserService.userRepository에 해당 참조 저장

**DI는 객체를 복사하는 과정이 아니라 참조를 전달하여 객체 간 연결을 구성하는 과정**

---
## 핵심 정리 및 배운점

DI - 의존성 주입
- 객체가 자신이 필요로 하는 의존 객체를 직접 생성하거나 찾는 대신 외부에서 전달받도록 하는 것

> Spring Container -> UserRepository 생성 -> UserService 생성 시 전달 -> UserService가 참조 보유

Ioc와 DI 관계

Ioc - 제어권을 외부로 넘기는 큰 원리

DI - 외부에서 Dependency를 주입하는 구체적인 방식

DI는 단순히 Spring이 객체를 대신 만들어주는 것이 아닌 객체가 자기 Dependency를 직접 만들거나 찾지 않도록 하고 **외부에서 필요한 객체를 전달하여 객체 간 관계를 구성하는 것**

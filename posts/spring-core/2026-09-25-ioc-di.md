## IoC(제어의 역전)
> 객체의 생성, 구성, 관리와 같은 제어권을 객체 자신이나 애플리케이션 코드가 아닌,
외부의 관리 주체가 담당하도록 만드는 설계 원리

---
## 메모리 내부

**Spring Boot가 실행**되면 **JVM 프로세스** 안에서 Spring FrameWork의 여러 객체가 만들어지고 서로 연결됨

> OS -> JVM Process -> Spring Boot Aplication -> AplicationContext -> BeanFactory 계열 -> Bean / Configuration / 기타 Spring 객체

IoC -> 메모리에 올라가는 **객체가 아님**

IoC를 구현하는 Spring 객체들
- JVM Process 내부에서 실행되는 Java 객체
- 객체 인스턴스는 JVM Heap 등을 사용

---
## 역할
> **객체 생성**과 **관리**에 대한 **제어권**을 **외부로 이동**시키는 것

기존: Application Code - 객체 생성, 객체 연결, 객체 관리 
Ioc: Aplication Code -> Spring container - 객체 생성, 객체 구성, 객체 관리

이렇게 설계하는 이유: 객체의 본래 책임과 객체를 조립하는 **책임을 분리**할 수 있음(SRP)

---
## 코드

```java
// 일반 Java
public class UserRepository {
}

public class UserService {
  private final UserRepository repository;

public UserService() {
  this.repository = new UserRepository
  }
}
```
UserService가 객체 생성의 **제어권**을 갖게됨

```java
// Spring Boot
@Repository
public class UserRepository {
  
}

@Service
public class UserService {
  private final UserRepository repository;
  
  public UserService(UserRepository repository) {
    this.repository = repository;
  }
}

@SpringBootAplication
public class Application {
  
  public static void main(String[] args) {
    SpringApplication.run(Application.class, args);
  }
}
```
Spring Container가 UserRepository / UserService의 **생성과 관리**를 해준다(책임 분리)

---
## 전체 흐름
```java
@SpringBootApplication
public class Aplication {
  public static void main(String[] args) {
    SpringApplication.run(Application.class, args);
  }
}
```
실행 시
> OS -> JVM -> SpringApplication.run() -> ApplicationContext 생성 -> Spring Ioc Container 초기화 -> Bean 구성 정보를 읽음 -> Bean 생성 및 구성 -> Bean을 Container가 관리 -> 애플리케이션 실행

JVM 메모리 관점
OS
|
JVM Process
  |
  | - ApplicationContext 객체
  | - BeanFactory 관련 객체
  | - Bean 객체
  | - 기타 Spring 객체

Ioc의 **역전**은 메모리에서 뭔가가 이동한다는 것이 아닌, **제어 흐름의 방향이 바뀌는 것**

---

## 핵심 정리 및 배운점
Ioc = 제어의 역전

핵심: 객체 생성, 구성, 관리의 제어권을 객체 자신이나 애플리케이션 코드에서 외부 관리 주체로 이동시키는 것

메모리 관점:
IoC 자체
- 메모리에 존재하는 객체가 아님
- 설계 원리

Spring의 Ioc 구현
- JVM 프로세스에서 실행되는 Java 객체들
- ApplicationContext, BeanFactory, Bean 등

Ioc가 단지 "Spring이 new를 대신 해준다" 가 아닌
객체의 제어권 자체를 외부의 Container로 넘기는 설계 원리

## Bean

> Spring Ioc Container가 **생성하고, 의존관계를 구성하며, 생명주기를 관리하는 객체**

-**Bean 등록 방식**-

1. Component Scan

> 특정 패키지에서 **Bean 등록 후보를 찾아 컨테이너에 등록하는 방식**

-대표 어노테이션-

| 어노테이션 | 역할 |
| --- | --- |
| @Component | 일반적인 Spring 관리 컴포넌트 |
| @Service | 서비스 계층의 컴포넌트 |
@Repository | 데이터 접근 계층의 컴포넌트
| @Controller | Spring MVC 컨트롤러
| @RestController | REST 응답 등을 처리 하는 컨트롤러

- @Service, @Repository, @Controller는 **@Component를 기반**으로 하는 **특수화된 어노테이션**

2. @Configuration, @Bean

> 개발자가 **객체 생성 방법을 명시적으로 지정**하고 Bean으로 등록하는 방식

```java
@Configuration
public class AppConfig {
  
 
  @Bean
  public Clock applicationClock() {
    // 반환된 객체가 Bean으로 등록됨
    return Clock.systemUTC(); 
  }
}
```

> 주로 **외부 라이브러리의 객체**처럼 클래스 자체에 @Component를 붙이기 **어려운 경우에 유용**

- @Configuration: **Bean 정의를 제공하는 설정 클래스**임을 나타냄
- @Bean: 메서드가 반환하는 객체를 Bean으로 등록

-**BeanDefinition**-

> Spring이 **Bean을 생성하고 구성하는 데 사용하는 메타데이터**

- 대상 클래스, Scope, 생성자 인자 등등의 구성 정보가 담김

> @Component / @Service / @Repository -> 컴포넌트 스캔 -> BeanDefinition -> Bean 인스턴스 생성

---
## 메모리 내부

> 운영체제 -> JVM 프로세스 -> Spring Boot 애플리케이션 -> ApplicationContext 및 BeanFactory 구현 객체 -> BeanDefinition과 실제 Bean 인스턴스

-**BeanDefinition과 Bean 인스턴스의 차이**-

> BeanDefinition -> 객체 생성에 필요한 구성 정보 -> Bean 인스턴스 생성 -> 의존관계 구성 -> 초기화 및 후처리 -> 컨테이너에서 사용할 Bean 

-**Singleton Bean과 메모리**-

> Spring의 기본 Bean Scope는 **singleton**

> Spring Container -> UserService singleton 인스턴스 <- Controller A / Controller B / 다른 Bean

---
## 역할

> Spring Container가 객체를 관리하고 여러 객체의 **의존관계를 구성할 수 있도록 하는 핵심 단위**

-**Bean 생명주기**-

> Bean이 생성되고 의존관계가 구성되며 초기화된 뒤 사용되고, **컨테이너 종료 시 필요한 정리 과정을 거치는 흐름**

> BeanDefinition 등록 -> Bean 인스턴스 생성 -> 의존성 주입 -> Aware 콜백 등 필요한 처리 -> BeanPostProcessor의 초기화 전 처리 -> 초기화 콜백 -> BeanPostProcessor의 초기화 후 처리 -> Bean 사용 -> ApplicationContext 종료 -> 소멸 콜백

1. 인스턴스 생성
 - BeanDefinition 등의 구성 정보를 바탕으로 실제 객체를 생성
 
2. 의존성 주입
 - 생성자나 설정된 주입 방식에 따라 필요한 의존 객체를 전달
 
3. Aware 콜백
 - 특정 Aware 인터페이스를 구현한 Bean은 Bean 이름이나 BeanFactory 등 컨테이너 관련 정보를 전달받을 수  있음
 
4. 초기화 전 후처리
 - BeanPostProcessor는 Bean 인스턴스의 초기화 전후에 개입할 수 있음
 
5. 초기화 콜백
 - 대표적인 초기화 방법은 아래 표 참고
 

| 방식 | 역할|
| --- | --- |
| @PostConstruct | 의존성 주입 후 초기화 작업 실행 |
| InitializingBean.afterPropertiesSet() |  Spring 인터페이스를 통한 초기화 콜백 |
| @Bean(initMethod = "...") | 별도로 지정한 초기화 메서드 실행 |

6. 초기화 후 후처리
 - BeanPostProcessor가 초기화 후 Bean을 처리
 
7. Bean 사용
 - 초기화가 완료되면 Bean은 다른 객체나 애플리케이션 코드에서 사용할 수 있음
 
8. 소멸 콜백
 - 관리 대상 Bean의 자원 정리를 위한 콜백을 실행할 수 있음
 

| 방식 | 역할 |
| --- | --- |
| @PreDestory | 종료 시 정리 작업 실행 |
| DisposableBean.destroy() | Spring 인터페이스를 통한 소멸 콜백 |
| @Bean(destroyMethod = "...") | 지정한 정리 메서드 실행 |

## AOP(관점 지향 프로그래밍)

> 여러 객체에 반복적으로 걸쳐 있는 공통 관심사를 핵심 비즈니스 로직과 분리하여 관리하는 프로그래밍 방식

**핵심 관심사**

- 사용자 생성
- 주문 생성
- 결제

**횡단 관심사**

- 로깅
- 트랜잭션
- 보안
- 성능 측정

AOP는 횡단 관심사를 별도의 코드로 분리하고 어떤 메서드에 언제 적용할지를 선언적으로 연결함

또한 **Spring AOP는 기본적으로 Proxy 기반으로 동작**

---
## 전체 구조

AOP 자체는 메모리에 존재하는 하나의 객체가 아님

AOP - 프로그래밍 방식 / 설계 원리

JVM 메모리 기준에서 중요한 부분은

- Target Object
- Proxy Object
- Aspect 관련 객체

예시: `UserService target`

애플리케이션의 다른 Bean이 UserService를 호출하는 것이 아닌 실제로는 **Proxy를 참조하고 있을 수 있음**

> 호출자 -> Proxy -> Advice 실행 -> Target Object -> 실제 메서드

- Target Object는 aspect의 적용 대상 객체
- AOP proxy는 aspect contract를 구현하기 위해 AOP framework가 생성하는 객체

> Proxy -> Target 객체

Proxy가 Target을 참조하면서 **메서드 호출을 중간에서 가로채는 구조**

---
## 역할

> 여러 객체에 반복적으로 등장하는 공통 기능을 비즈니스 로직에서 분리하고 특정 실행 지점에 자동으로 적용하는 것

예시: `UserService`, `OrderService`

-필요한 것-

> 로그 기록, 실행 시간 측정, 트랜잭션, 권한 검사

AOP 없이 작성

> UserService - 비즈니스 로직, 로그 | OrderService - 비즈니스 로직, 로그

AOP 사용

> UserService - 비즈니스 로직 | OrderService - 비즈니스 로직 | Logging Aspect - 로그 기능

> Logging Aspect -> 어떤 메서드에 적용할지 지정 -> Proxy 생성 -> 해당 메서드 호출을 proxy가 가로챔

Aspect - 공통 관심사를 모아놓은 단위

Advice - 실제로 실행할 부가 기능의 코드

Pointcut - 어떤 메서드에 Advice를 적용할지 결정하는 조건

## 코드

```java
@Service
public class UserService {
  
  public void createUser() {
    System.out.println("사용자 생성");
  }
}
```
```java
@Aspect
@Component
public class LoggingAspect {
  @Around("execution(* com.example.service..*(..))")
  public Object logging(ProceedingJoinPoint joinPoint) throws Throwable {
    
    long start = System.currentTimeMillis();
    
    System.out.println(
                "호출 시작: " + joinPoint.getSignature()
        );

        Object result = joinPoint.proceed();

        long end = System.currentTimeMillis();

        System.out.println(
                "실행 시간: " + (end - start) + "ms"
        );

        return result;
  }
}
```
**주요 코드**

`@Aspect` - 이 클래스가 Aspect임을 나타냄

`@Around` - 대상 메서드 실행 전후를 감싸는 Advice

`execution(* com.example.service..*(..))` - Pointcut

> com.example.service -> 그 하위 패키지 -> 모든 메서드

---
## 전체 흐름

> OS -> JVM -> ApplicationContext 생성 -> Bean 구성 -> UserService / LoggingAspect 가각 Bean 생성 -> Spring이 AOP 적용 대상 확인 -> Proxy 생성 -> Container에서 해당 Bean을 Proxy 기반으로 관리

AOP는 기존 객체의 코드를 수정 하는 개념이 아님

> 호출자 -> Proxy -> 공통 기능 -> 실제 객체

호출 경로를 구성하는 것

---

## 핵심 정리 및 배운점

AOP - 여러 객체에 공통적으로 걸쳐 있는 관심사를 핵심 비즈니스 로직과 분리하고 필요한 실행 지점에 적용하는 프로그래밍 방식

**핵심 기능**
- 사용자 생성
- 주문 생성
- 결제

**횡단 관심사**
- 로그
- 트랜잭션
- 보안
- 성능 측정

**핵심 구조**

> Aspect -> Advice -> Pointcut -> Proxy -> Target Object의 메서드 실행


Aspect - 공통 관심사를 모듈화한 것

Advice - 실제 실행할 부가 기능

Pointcut - 어느 메서드에 적용할지 결정

Join Point - Advice가 적용되는 실행 지점

Proxy - 호출을 가로채 Advice를 실행하고 Target으로 넘기는 객체

Target - 실제 비즈니스 로직을 가진 객체

## 한 줄 정의
클로저(closure)는 함수와 그 함수가 만들어질 때의 주변 변수 환경을 한데 묶은 것으로, 바깥 함수가 실행을 마친 뒤에도 안쪽 함수가 그 변수를 계속 참조할 수 있게 한다.

## 왜 필요한가
함수 안에서 선언한 변수는 함수가 끝나면 사라진다. 그런데 "부를 때마다 1씩 커지는 숫자"처럼 호출 사이에 값을 기억해야 할 때가 있다. 전역 변수에 두면 아무 데서나 바꿀 수 있어 위험하고, 매개변수로 매번 넘기면 번거롭다. 클로저는 변수를 바깥에서 숨긴 채 특정 함수만 계속 쓰게 해 준다.

## 핵심
1. **스코프는 코드를 쓴 위치로 정해진다.** 스코프(scope)는 변수를 찾을 수 있는 범위다. 자바스크립트는 함수를 어디서 호출했는지가 아니라 어디에 적었는지로 변수를 찾는데, 이를 렉시컬 스코프(lexical scope)라 한다. 안쪽 함수는 자기가 적힌 자리의 바깥 변수를 볼 수 있다.
2. **함수는 만들어질 때 주변 환경을 기억한다.** 함수 객체가 생성되는 순간 자기를 둘러싼 변수 환경의 참조가 함수 안에 저장된다. 그래서 함수를 다른 곳으로 넘기거나 한참 뒤에 호출해도 원래 자리의 변수를 찾는다.
3. **바깥 함수가 끝나도 변수는 살아 있다.** 함수가 반환되면 지역 변수는 보통 가비지 컬렉션(더 쓰지 않는 메모리를 자동으로 회수하는 일)으로 사라진다. 그러나 안쪽 함수가 참조하는 변수는 회수되지 않는다. 안쪽 함수가 살아 있는 한 변수도 산다.
4. **값의 복사가 아니라 변수의 참조다.** 클로저는 만들어진 순간의 값을 찍어 두지 않고 변수 자체를 가리킨다. 나중에 변수가 바뀌면 클로저도 바뀐 값을 본다.
5. **호출마다 새 환경이 생긴다.** 바깥 함수를 두 번 호출하면 변수 환경도 두 개 생기고, 각각 반환된 안쪽 함수는 서로 다른 환경을 붙든다. 이 성질로 독립된 상태를 가진 함수를 여러 개 찍어 낼 수 있다.

## 예시
```js
function makeCounter() {
  let count = 0;             // 바깥에서는 직접 손댈 수 없다
  return function () {
    count += 1;              // 자기가 적힌 자리의 count를 찾는다
    return count;
  };
}

const counterA = makeCounter();
const counterB = makeCounter();

console.log(counterA()); // 1
console.log(counterA()); // 2
console.log(counterB()); // 1
```
`makeCounter`가 끝났는데도 반환된 함수가 `count`를 붙들고 있어 값이 유지되고, A와 B는 서로 다른 `count`를 가진다.

```js
function makeAdder(x) {
  return function (y) {
    return x + y;
  };
}

const add5 = makeAdder(5);
const add10 = makeAdder(10);

console.log(add5(2));  // 7
console.log(add10(2)); // 12
```
같은 함수 본문이지만 `add5`는 `x`가 5인 환경을, `add10`은 `x`가 10인 환경을 각각 기억한다.

## 자주 하는 실수
**1. 반복문 안에서 `var`로 클로저 만들기**
```js
for (var i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i);
  }, 0);
}
// 3 3 3
```
`var`는 블록 스코프가 아니라 함수 스코프라 `i`가 반복문 전체에 하나뿐이다. 세 함수가 같은 `i`를 참조하고, 실제로 실행되는 시점에는 반복이 끝나 `i`가 3이다.
```js
for (let i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i);
  }, 0);
}
// 0 1 2
```
`let`(ES2015 이상)은 반복 회차마다 새 `i`를 만들어 각 함수가 자기 회차의 `i`를 붙든다.

**2. 클로저가 값을 "찍어 둔다"고 생각하기**
```js
function make() {
  let x = 1;
  const get = function () { return x; };
  x = 2;
  return get;
}
console.log(make()()); // 2
```
`get`이 만들어질 때 `x`는 1이었지만, 클로저는 값이 아니라 변수를 참조하므로 호출 시점의 값인 2가 나온다. 그 시점의 값이 필요하면 따로 담아 두어야 한다.
```js
function make() {
  let x = 1;
  const fixed = x;                             // 이 시점의 값을 따로 담는다
  const get = function () { return fixed; };
  x = 2;
  return get;
}
console.log(make()()); // 1
```

**3. 숨긴 변수를 바깥에서 꺼내려 하기**
```js
const counter = makeCounter();
console.log(counter.count); // undefined
```
`count`는 함수의 속성이 아니라 함수가 참조하는 환경 속 변수라 바깥에서 접근할 길이 없다. 읽어야 하면 읽는 함수를 함께 반환한다.
```js
function makeCounter() {
  let count = 0;
  return {
    next() { count += 1; return count; },
    value() { return count; }
  };
}
const counter = makeCounter();
counter.next();
console.log(counter.value()); // 1
```

## 한 줄 요약
함수는 태어난 자리의 변수를 기억하고, 그 함수가 살아 있는 한 변수도 죽지 않는다.

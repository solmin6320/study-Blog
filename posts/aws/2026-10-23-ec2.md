## VPC

> AWS 리소스를 **논리적으로 격리된 가상 네트워크 안에 배치**하고 리소스 간의 **네트워크 통신과 연결 경로를 구성할 수 있도록 제공**하는 서비스

VPC = AWS 인프라 위에서 논리적으로 격리된 가상 네트워크

---
## 전체 구조

AWS 리소스를 배치하고 네트워크 통신 경로를 구성하는 가상 네트워크

> VPC -> IP 주소 범위 -> Subnet -> AWS 리소스

- VPC 안에 여러 서브넷을 구성하여 웹 서버, 애플리케이션 서버 등을 구분할 수 있음

-**CIDR**-

VPC 에서 사용할 IP 주소의 범위를 나타내는 표기법

> VPC -> 10.0.0.0/16

- 10.0.0.0/16은 IPv4 주소를 표현하는 네트워크 범위

-**Subnet**-

VPC의 IP 주소 범위를 더 작은 네트워크 범위로 나눈 것

> VPC -> Subnet -> EC2 / RDS 등의 리소스

- Public Subnet - 인터넷에서 접근해야 하는 리소스 배치
- Private Subnet - 외부에서 직접 접근할 필요가 없는 애플리케이션 서버나 데이터베이스 배치

-**Route Table**-

네트워크 트래픽을 어디로 전달할지 결정하는 규칙들의 집합

- Destination - 트래픽이 향하는 목적지 IP 주소 범위
- Target - 해당 트래픽을 전달할 대상

예시 규칙 설정
| Destination | Target | 의미 |
| --- | --- | --- |
| 10.0.0.0/16 | local | VPC 내부 네트워크로 전달 |
| 0.0.0.0/0 | igw-xxxxxxx | 인터넷 게이트웨이로 전달 |

-**Internet Gateway(IGW)**-

VPC와 인터넷 사이의 통신을 가능하게 하는 게이트웨이
 >VPC -> Internet Gateway -> Internet

-**NAT Gateway**-

private Subnet의 리소스가 인터넷으로 나가는 IPv4 통신을 할 수 있도록 지원하는 네트워크 구성 요소

> Private Subnet의 EC2 -> NAT Gateway -> Internet

- NAT Gateway를 사용하려면 관련 라우팅 설정이 필요
- NAT Gateway는 별도 비용이 발생할 수 있음

-**Security Group**-

EC2 등의 리소스에 연결하여 인바운드와 아웃바운드 네트워크 트래픽을 제어하는 가상 방화벽

예시 포트
- 22 -> SSH
- 80 -> HTTP
- 443 -> HTTPS

-**Network ACL**-
서브넷 수준에서 네트워크 트래픽을 허용하거나 거부하는 규칙

Security Group과 NACL의 차이
- Security Group -> 리소스 수준의 트래픽 제어, 상태 저장 방식
- Network ACL -> 서브넷 수준의 트래픽 제어, 상태 비저장 방식

---
## 역할

> AWS 리소스의 네트워크 환경을 직접 설계하고 관리하기 위해서

VPC는 IP 주소 범위, 서브넷, 라우팅 경로, 게이트웨이 등등의 규칙을 구성할 수 있음

- 외부 사용자 -> 웹 애플리케이션 접근
- ALB -> 요청을 애플리케이션 서버로 전달
- EC2 -> Spring Boot
- RDS -> 관게형 데이터베이스 저장 및 조회

> Internet -> Public Subnet의 ALB -> private Subnet의 EC2 -> Private Subnet의 RDS

즉, VPC는 단순히 EC2를 담는 공간이 아닌 **AWS 리소스 간 네트워크 연결과 격리를 설계하는 기반**

---
## 전체 흐름

1. 개발자가 VPC 생성 요청

> 개발자 -> AWS Console / CLI / SDK -> AWS API -> VPC Control Plane

2. VPC의 주소 범위 설정
> VPC -> 10.0.0.0/16

- 이후 서브넷을 생성 시 해당 범위 안에서 **더 작은 IP 주소 범위를 할당**

3. Subnet 생성

> VPC -> Subnet -> EC2 / RDS 등의 리소스 배치

- VPC 내부에 서브넷을 생성 및 각 서브넷이 위치할 AZ를 지정

4. Route Table 설정

> Subent -> Route Table -> 통신 경로 결정

5. Internet Gateway와 네트워크 보안 설정

> VPC -> Internet Gateway -> Internet

- Security Group과 필요에 따른 NACL 규칙을 구성

6. EC2와 RDS 연결

> VPC -> Subnet -> ENI -> EC2 -> Spring Boot

7. 실제 사용자 요청 전달

> 사용자 -> Internet -> Internet Gateway -> Public Subnet의 ALB -> Private Subnet의 EC2 -> Spring Boot -> RDS

## 핵심 정리 및 배운점

- VPC - AWS 리소스를 배치하고 네트워크 연결을 구성하는 논리적으로 격리된 가상 네트워크

- CIDR - 네트워크에서 사용할 IP 주소 범위를 나타내는 표기법
- Subnet - VPC의 IP 주소 범위를 나누어 리소스를 배치하는 네트워크 범위
- Route Table - 목적지에 따라 네트워크 트래픽을 전달할 경로를 결정하는 규칙의 집합
- Internet Gateway - VPC와 인터넷 사이의 통신을 가능하게 하는 게이트웨이
- NAT Gateway - Private Subnet의 리소스가 외부 인터넷으로 나가는 IPv4 통신을 할 수 있도록 지원하는 구성 요소
- Security Group - 리소스 수준에서 인바운드와 아웃바운드 트래픽을 제어하는 가상 방화벽
- Network ACL - 서브넷 수준에서 트래픽을 허용하거나 거부하는 규칙
- ENI - EC2 등의 리소스를 VPC 네트워크에 연결하는 가상 네트워크 인터페이스

-흐름-
> 개발자 -> AWS Console -> AWS API -> VPC 생성 -> CIDR 설정 -> Subent 생성 -> Route Table 설정 -> Gateway 연결 -> Security Group / NACL 설정 -> EC2 / RDS 배치 -> EC2 / RDS 배치 -> 실제 네트워크 통신

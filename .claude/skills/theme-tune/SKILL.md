# 테마·색 조정

## 원칙

**`css/tokens.css`만 고친다.** 다른 CSS 파일을 건드려야 색이 바뀐다면, 그건 토큰 시스템이 깨졌다는 신호이므로 그 사실을 먼저 보고한다.

## 1. 요청을 값으로 번역

사용자는 "너무 밝아", "차분하게" 같은 감각어로 말한다. 그걸 토큰 변경으로 바꾼다:

| 요청 | 조정할 토큰 |
|---|---|
| 너무 밝다/눈부시다 | `--c-bg`, `--c-surface` 명도 ↓, 배경 메시 opacity ↓ |
| 칙칙하다 | 액센트 채도 ↑, 메모지 색 채도 ↑ (본문 대비는 유지) |
| 차분하게 | 채도 전반 ↓, 액센트를 한 계열로 통일 |
| 글자가 흐리다 | `--c-text` 대비 ↑ (4.5:1 미달이면 무조건 수정) |
| 다크모드가 눈아프다 | 다크에서 메모지 파스텔 배경을 제거하고 어두운 표면 + 색 테두리로 |
| 메모지 색이 유치하다 | 채도 ↓ + 명도 ↑ (파스텔은 채도가 높으면 싸구려가 된다) |

**어느 토큰을 왜 바꾸는지 먼저 설명하고 고친다.** 말없이 여러 값을 한꺼번에 흔들면 어떤 변경이 효과를 냈는지 알 수 없다.

## 2. 반드시 함께 검증할 것

색을 바꾸면 **라이트와 다크 양쪽**을 다 확인한다. 한쪽만 보고 끝내는 것이 가장 흔한 실수다.

| 항목 | 기준 |
|---|---|
| 본문 텍스트 | 배경 대비 4.5:1 이상 |
| 보조 텍스트 `--c-text-dim` | 3:1 이상 |
| 링크 | 본문과 구분되면서 대비 충족 |
| 메모지 6색 위의 글자 | 6색 × 라이트/다크 = **12가지 조합 전부** 확인 |
| 코드블록 | 하이라이팅 색이 배경 위에서 읽히는가 |
| 포커스 링 | 모든 배경 위에서 보이는가 |

## 3. 메모지 색을 바꿀 때

`--memo-*`와 `--memo-*-ink`는 **쌍으로** 바꾼다. 배경만 바꾸면 글자가 안 읽힌다.
다크모드에서는 파스텔 배경을 그대로 쓰지 말고, 어두운 표면에 색을 테두리·라벨로만 남기는 전략을 유지한다.

## 4. 바꾸면 안 되는 것

- 토큰 **이름** — 이름을 바꾸면 계약 위반이다. 값만 바꾼다. 이름을 바꿔야 하면 `/contract-update`
- 다크모드 구조 — `:root[data-theme="dark"]`에서 토큰만 재정의하는 구조를 유지한다

## 5. 보고

바꾼 토큰의 **이전 값 → 새 값**을 표로, 의도 한 줄씩. 대비 검증 결과 포함.
사용자가 되돌리고 싶어할 수 있으므로 이전 값을 반드시 남긴다.

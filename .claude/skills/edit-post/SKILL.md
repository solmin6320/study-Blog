# /edit-post — 기존 글은 사용자가 에디터 수정 모드에서 고친다

새 글은 `/new-post`. 이 스킬은 **이미 있는 글**을 고치려 할 때 안내만 한다.

## 왜 에이전트가 고치지 않는가

- 글의 본문과 frontmatter 값은 **사용자 데이터**다(CLAUDE.md "posts/의 소유 범위"). 푸터 "게시글은 모두 직접 작성하고 정리하였습니다"가 공개되므로 오타 하나도 에이전트가 고치지 않는다(meeting-08 U6).
- 에디터로 저장하면 서버가 **`created`를 보존하고 `updated`만 갱신**한다(절대 규칙 4, `docs/api.md` §2). 손편집은 이 보장을 사람의 기억에 맡긴다.

**하지 않는 것**: `.md` 본문·frontmatter 편집 · `index.json` 항목 고치기 · id 바꾸기. (파생 파일 `index.json`이 `.md`와 **어긋난** 것을 `.md` 값으로 맞추는 정합성 작업만 frontend-dev 몫이고, 사용자 통보 + 단독 커밋이 조건이다.)

## 안내 절차

1. **대상 찾기** — 사용자가 제목만 말하면 `posts/index.json`을 **읽어서** id를 찾아 준다(읽기만). 후보가 여럿이면 제목·게시일을 보여 주고 고르게 한다.
2. **서버** — `/new-post` 1·2단계와 같다(서버 켜짐 · 커밋 신원).
3. **열기** — `http://localhost:5500/write.html?id=<id>` (또는 글 화면의 관리자 `수정` 링크). 불러온 뒤 고치고 **저장(Ctrl+S)**.
   - 게시일은 그대로, 수정일만 바뀐다. 같은 날 고친 글은 수정일을 따로 보이지 않는다(2026-09-23 U8-A).
   - 다른 탭에서 같은 글을 먼저 저장했으면 에디터가 덮어쓰지 않고 알린다(`409 stale`, api.md v1.2).
   - **id는 되도록 바꾸지 않는다** — 바꾸면 옛 `post.html?id=` 링크가 끊긴다. 바꾸려는 id에 이미 다른 글이 있으면 서버가 거절한다(`409 exists`).
4. **확인·공개** — 글 화면을 새로고침해 내용·수정일을 본다. 공개는 `/ship`.

## 에이전트가 도울 수 있는 것

- 글을 **읽고** 틀린 설명·오타·깨진 마크다운의 위치를 `파일:줄`로 알려 주기. 고칠 문장을 대신 써 주지 않는다 — 무엇이 왜 틀렸는지만.

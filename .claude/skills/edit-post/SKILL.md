# 기존 글 수정

새 글 작성은 `/new-post`. 이 스킬은 **이미 있는 글을 고칠 때**만 쓴다.

## 1. 대상 특정

```bash
grep -l "제목키워드" posts/*.md
```
후보가 여럿이면 제목·날짜를 보여주고 **어느 글인지 사용자에게 확인받는다.** 엉뚱한 글을 덮어쓰면 복구가 어렵다.

## 2. 수정 전 원본 확보 (필수)

```bash
head -15 posts/<id>.md    # frontmatter 확인
```
**`created` 값을 정확히 메모한다.** 이걸 놓치면 게시일이 오늘로 바뀌어버린다 — 사용자가 명시적으로 요구한 기능이 깨지는 것이다.

## 3. 수정 규칙

| 필드 | 규칙 |
|---|---|
| `id` | **바꾸지 않는다.** 바꾸면 링크가 전부 깨진다. 꼭 바꿔야 하면 사용자에게 링크 변경을 경고하고 승인받는다 |
| `created` | **원본 값 그대로.** 절대 갱신하지 않는다 |
| `updated` | **현재 시각으로 갱신.** `date -Iseconds`로 실제 시각을 확인하고 KST(+09:00) ISO 8601로 |
| `title`/`summary`/`tags`/`category`/`color`/`pinned` | 요청대로 수정 가능 |

파일명은 `id`와 항상 일치해야 한다.

## 4. index.json 동기화 (놓치기 쉬움)

`.md`만 고치고 `index.json`을 안 고치면 **목록에는 옛날 제목이, 본문에는 새 제목이** 뜬다.
수정한 필드를 `posts/index.json`의 해당 항목에도 똑같이 반영한다. 본문은 넣지 않는다.

## 5. 검증

```bash
grep -c '"id"' posts/index.json ; ls posts/*.md | wc -l    # 개수 일치 확인
```
- `created`가 원본과 같은가 (수정 전 메모한 값과 대조)
- `updated`가 오늘인가
- `.md`의 frontmatter와 `index.json` 항목의 값이 전부 일치하는가

## 6. 보고

무엇을 어떻게 고쳤는지, `created`/`updated`가 각각 어떤 값인지 명시해서 한국어로 보고한다.
로컬 서버가 떠 있으면 새로고침해서 **수정 날짜 표시가 실제로 바뀌었는지** 확인하라고 안내한다.

# 디자인 감사

`css/*`를 **실제로 읽고** 판정한다. 추측 금지, `파일:줄`로 근거를 댄다.

## 체크리스트

### 1. 토큰 일관성 (가장 먼저 — 기계적으로 검사 가능)
```bash
grep -nE '#[0-9a-fA-F]{3,8}\b|rgba?\(' css/*.css | grep -v tokens.css
```
`tokens.css` 밖에 리터럴 색상값이 있으면 **결함**이다. 단 `color-mix()`·변수 기반 알파 조합은 허용.
간격도 마찬가지: `--sp-*` 대신 `px`가 흩어져 있으면 시스템이 무너진 것이다.

### 2. 가독성
- 본문 `.prose` 폰트 크기 17px 이상, 행간 1.7 이상, 줄길이 65~75자(`--w-content`)
- h1~h4의 크기 차이가 **한눈에** 구분되는가. 인접 위계의 크기 비율이 1.15배 미만이면 위계가 안 보인다
- 본문 텍스트 대비 4.5:1 이상, 보조 텍스트(`--c-text-dim`)도 3:1 이상
- 다크모드에서 순수 흑백(#000/#fff)을 쓰고 있지 않은가

### 3. 시선 흐름
- 첫 화면에서 눈이 어디로 먼저 가는가. 메모지들이 균일해서 "어디부터 봐야 할지" 모르겠으면 위계 실패다
- 카드 안 요소 순서: 카테고리 → 제목 → 요약 → 태그 → 날짜. 날짜가 제목보다 눈에 띄면 잘못됐다
- 여백이 그룹을 만드는가. 관련된 것끼리 가깝고 다른 것끼리 멀어야 한다

### 4. 모션
- 동시에 움직이는 요소가 3개를 넘는 구간이 있는가 (산만함)
- `transform`/`opacity` 외의 속성을 애니메이션하고 있는가 (성능 결함)
- `@media (prefers-reduced-motion: reduce)` 블록이 실제로 존재하고 모든 애니메이션을 덮는가
- 카드 회전이 ±0.6deg를 넘는가 (싸구려로 보임)

### 5. 반응형 붕괴 지점
- 360px에서 가로 스크롤을 만드는 고정 `width`/`min-width`가 있는가
- 타이포가 `clamp()`로 유동적인가, 아니면 미디어쿼리로 계단식인가
- 터치 타깃 44px 미만인 버튼이 있는가

### 6. 다크모드
- `:root[data-theme="dark"]`에서 **토큰만** 재정의하는가, 컴포넌트 규칙을 다시 쓰는가(후자면 유지보수 지옥)
- 메모지 파스텔색을 다크에서 그대로 쓰고 있는가 (눈이 아프다 — 어두운 표면 + 색은 액센트로만)

## 보고 형식

심각도(치명/중대/경미)순으로. 각 항목에 `파일:줄` + **왜 문제인지** + **구체적 수정안**(값까지).
"예쁘게 하자" 같은 말은 보고서가 아니다.

# /new-post — 새 글은 사용자가 write.html에서 직접 쓴다

## 왜 에이전트가 쓰지 않는가

- 공개 사이트 푸터가 **"게시글은 모두 직접 작성하고 정리하였습니다"** 라고 말한다(2026-09-23 사용자 확정). 에이전트가 쓴 글 한 편이 그 문장을 거짓으로 만든다.
- 사용자 결정 **U2 = (A) 대필 경로 폐기**(2026-09-23, `docs/HANDOFF.md` §9). 글 저장 경로는 에디터 서버 하나다(CLAUDE.md "글 추가 흐름").
- 손으로 `.md`·`index.json`을 쓰던 옛 절차는 `created` 드리프트의 원인이었다(meeting-08 D15, 계약 §9).

**하지 않는 것**: `posts/**`에 `.md`를 만들기 · `posts/index.json`·`categories.json` 고치기 · 글 본문 초안을 대신 써 주기 · 사용자가 준 메모를 "정리해서" 글로 바꾸기.
사용자가 "정리해서 올려줘"라고 하면 위 이유를 한 줄로 말하고, 아래 안내로 넘어간다.

## 안내 절차

1. **서버가 켜져 있는가** — `curl -s http://localhost:5500/api/health`가 `{"ok":true,…}`이면 켜져 있다.
   꺼져 있으면: Docker Desktop을 켠 뒤 프로젝트 폴더에서 `start.bat`(또는 `docker compose up`). 절차·포트 충돌은 `/serve`.
   **Docker가 없는 PC에서는 저장할 수 없다** — 에디터에서 쓸 수는 있고 초안은 브라우저에 임시저장되지만, 저장 버튼이 잠겨 있다.
2. **커밋 신원** — 없으면 저장은 되지만 커밋이 매번 건너뛰어진다(덮어쓴 글을 되돌릴 이력이 없다). `/serve` §0으로 먼저 확인하라고 안내한다.
3. **쓰기** — 브라우저에서 `http://localhost:5500/write.html`. 제목 · 분류 · 본문을 쓰고 **저장(Ctrl+S)**. 서버가 `posts/<분류>/<id>.md`와 `index.json`을 쓰고 게시일(`created`)을 찍는다.
   - 같은 날 비슷한 제목(예: `Java 정리` 다음 `Java 복습`)이면 자동 id가 겹칠 수 있다 — 에디터가 알린다(계약 §6-1). 알림이 뜨면 그대로 따르면 된다.
   - 그래프·그림은 이미지 파일을 `posts/<분류>/img/`에 직접 넣고 본문에 `![설명](posts/java/img/a.png)`처럼 쓴다(2026-09-23 U4 "규칙만" — 업로드 버튼은 없다). `img/a.png`(글 기준 상대 경로)나 `/posts/…`는 공개 사이트에서 깨진다.
4. **공개** — 저장만으로는 로컬에만 있다. 공개하려면 사용자가 `/ship`(커밋·푸시). 푸시는 `gh auth login` 뒤에만 된다.

## 에이전트가 도울 수 있는 것

- 개념 설명, 사용자가 쓴 글의 **오류·오타 지적**(고쳐 주지 않는다 — 어디가 왜 틀렸는지만), 마크다운 문법 질문에 답하기.
- 에디터 사용법(단축키·코드 블록·표) 안내 — 진실은 계약 §6-2 표.

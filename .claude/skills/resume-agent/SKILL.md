# /resume-agent — 끊긴 에이전트 이어가기

에이전트는 끊겨도 **디스크에 쓴 것은 남아 있고, 자기 transcript도 기억한다.** 새로 띄우면 처음부터 다시 하므로 토큰이 두 배 든다. `SendMessage`로 같은 에이전트를 재개한다.

## 절차

1. **원인 확인** — 알림의 error type:
   - `rate_limit` → "resets N시" 이후에 재개. 지금이 그 전이면 사용자에게 알리고 기다린다.
   - `content filtering` → 대개 픽스처 내용이나 예시 문자열이 우연히 걸린 것. 재개 메시지에 "픽스처는 평범한 학습 메모 주제로"를 덧붙인다.
   - 그 외 → 그냥 재개.

2. **진행 상태 파악** — 알림의 마지막 `result` 문장(어디까지 갔는지)과 디스크를 대조한다:
   ```bash
   git status --short
   grep -n "<지시했던 함수·클래스명>" <소유 파일>
   ```
   구현이 남아 있으면 "구현은 돼 있다", 없으면 "구현 전"으로 판정.

3. **재개 메시지** — 이 네 가지만:
   - 왜 끊겼는지 한 줄
   - 디스크에 남아 있는 것(파일·함수명) — "다시 구현하지 마라"
   - 남은 단계 번호 목록(검증 → 픽스처 삭제 → 서버 종료 → 보고)
   - 보고 형식 한 줄
   ```
   SendMessage(to: <agentId>, message: ...)
   ```

4. 재개 후 또 끊기면 원인이 반복되는 것이다. 작업을 더 작게 쪼개서 새로 띄운다.

## 하지 않는 것

- 끊긴 에이전트의 작업을 오케스트레이터가 대신 마무리하지 않는다(소유권·맥락이 어긋난다).
- 같은 프롬프트로 새 에이전트를 띄우지 않는다.

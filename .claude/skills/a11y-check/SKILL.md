# 접근성 점검

공개 배포하는 블로그다. 접근성은 선택이 아니다.

## 1. 키보드만으로 전부 되는가

- `<div onclick>` 같은 가짜 버튼이 있는가 → 실제 `<button>`이어야 한다
```bash
grep -n 'onclick\|addEventListener(.click' *.html js/*.js
```
클릭 핸들러가 붙은 요소가 `button`/`a`가 아니면 결함이다.
- Tab 순서가 시각적 순서와 일치하는가 (`tabindex` 양수값이 있으면 거의 항상 잘못됨)
- 모달: 열리면 포커스가 안으로 들어가고, 트랩되고, ESC로 닫히고, 닫히면 **열기 전 요소로 복귀**하는가
- 에디터 textarea에서 Tab이 들여쓰기로 동작한다면, **Escape+Tab으로 빠져나갈 수 있어야** 한다(키보드 사용자 탈출구)

## 2. 포커스 가시성

```bash
grep -n 'outline\s*:\s*none\|outline\s*:\s*0' css/*.css
```
`outline:none`이 있는데 `:focus-visible` 대체 스타일이 없으면 **치명적 결함**이다.

## 3. 시맨틱 구조

- 페이지마다 `<h1>`이 정확히 하나인가
- 제목 레벨이 건너뛰지 않는가 (h2 다음 h4 금지) — 마크다운 본문도 포함
- `header`/`nav`/`main`/`article`/`footer`를 쓰는가, 전부 `div`인가
- 스킵 링크(`.sr-only` 본문 바로가기)가 첫 번째 포커스 요소인가

## 4. 이름과 설명

- 아이콘만 있는 버튼(`.icon-btn`)에 `aria-label`이 있는가
- `<img>`에 `alt`가 있는가. 장식 이미지는 `alt=""`
- 폼 입력마다 `<label>` 또는 `aria-label`이 연결됐는가 (에디터 필드 전부 확인)
- 동적으로 내용이 바뀌는 영역(`#board`, 토스트)에 `aria-live`가 있는가
- 현재 페이지 네비 링크에 `aria-current="page"`

## 5. 색과 대비

- 본문 4.5:1, 큰 글씨·UI 요소 3:1 이상
- **색만으로 정보를 전달하는 곳이 있는가** — 예: 메모지 색으로만 카테고리를 구분하면 색각 이상 사용자에게 무의미하다. 텍스트 라벨이 함께 있어야 한다
- 다크/라이트 **양쪽** 모두 검사한다

## 6. 모션

```bash
grep -n 'prefers-reduced-motion' css/*.css js/*.js
```
CSS에만 있고 JS 애니메이션(stagger 지연, 스크롤 효과)이 그대로면 절반만 대응한 것이다.

## 7. 기타

- `<html lang="ko">`가 있는가
- 확대 금지(`user-scalable=no`, `maximum-scale=1`)를 걸었는가 → 접근성 위반
- 링크 텍스트가 "여기", "클릭"인가 → 맥락 없이 의미가 통해야 한다

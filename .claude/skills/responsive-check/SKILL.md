# 반응형 점검

기준 폭: **360 / 768 / 1024 / 1440px**. 360px에서 가로 스크롤이 생기면 실패다.

## 1. 가로 스크롤 유발 용의자 (기계적 검사)

```bash
grep -nE 'width\s*:\s*[0-9]{3,}px|min-width\s*:\s*[0-9]{3,}px' css/*.css
grep -n 'white-space\s*:\s*nowrap' css/*.css
grep -n 'overflow-x' css/*.css
```
- 360px보다 큰 고정 `width`/`min-width`가 미디어쿼리 밖에 있으면 결함
- 긴 URL·코드가 넘치는가 → `.prose` 에 `overflow-wrap:anywhere` 또는 `word-break` 대책이 있는지 확인
- 표는 반드시 `.table-wrap` 안에서 스크롤되어야 한다. `.prose table` 자체가 페이지를 밀면 안 된다
- `pre` 코드블록에 `overflow-x:auto`가 있는가

## 2. 유동 스케일

```bash
grep -c 'clamp(' css/*.css
grep -n '@media' css/*.css
```
- 타이포·여백이 `clamp()`로 유동적인가, 아니면 미디어쿼리로 계단식 점프하는가
- 미디어쿼리가 20개를 넘어가면 시스템이 아니라 땜질이다

## 3. 폭별 레이아웃 의도 확인

| 폭 | 기대 동작 |
|---|---|
| 360 | 메모지 1열, 헤더 액션 축약, TOC 숨김 또는 접힘, 에디터는 쓰기 모드 단일 화면 |
| 768 | 메모지 2열, 툴바 줄바꿈 허용 |
| 1024 | 메모지 3열, 본문 옆 TOC 등장 |
| 1440 | 최대 폭(`--w-page`)에서 멈추고 가운데 정렬. 무한정 늘어나면 안 된다 |

각 폭에서 실제로 그렇게 되는지 CSS를 읽어 확인하고, 안 되는 지점을 `파일:줄`로 지목한다.

## 4. 모바일 전용 함정

- `100vh` 사용 → 모바일 주소창 때문에 잘린다. `100dvh` 또는 `min-height` 조합인지 확인
- `position:fixed` 헤더가 본문을 가리는가 (`scroll-margin-top`, `padding-top` 보정 확인)
- hover 전용 인터랙션이 모바일에서 접근 불가가 되는가 — **코드 복사 버튼이 hover에만 뜨면 모바일에서 영영 못 누른다.** `@media (hover:hover)` 분기가 있는지 확인
- 터치 타깃 44×44px 미만인 버튼·칩·태그
- 에디터: 360px에서 좌우 분할이 강제되면 못 쓴다. 단일 모드로 전환되는가

## 5. 이미지·미디어

- `img { max-width:100% }` 전역 보장
- 콘텐츠 이동(CLS)을 막을 `aspect-ratio` 또는 크기 지정

# 외부 의존성 추가 요청

사용자가 명시한 규칙: **외부 의존성이 필요하면 먼저 묻는다. Node.js는 되도록 쓰지 않는다.**
이건 협상 대상이 아니다. 승인 없이 추가하면 규칙 위반이다.

## 현재 승인된 의존성

| 라이브러리 | 용도 |
|---|---|
| jQuery 3.7.1 | 애니메이션·DOM |
| marked.js 12.0.2 | 마크다운 → HTML |
| highlight.js 11.9.0 | 코드 하이라이팅 |
| DOMPurify 3.1.6 | XSS 살균 (필수) |

**명시적으로 제외된 것: Chart.js, KaTeX** — 사용자가 "표나 그래프는 쓸 가능성이 작다"고 판단했다. 나중에 필요해지면 다시 물어야 한다.

## 1. 먼저 — 정말 필요한가

추가 전에 확인:
- 승인된 4개로 해결되는가 (예: 간단한 다이어그램은 SVG를 직접 그리면 된다)
- 50줄 남짓의 바닐라 JS로 대체 가능한가 → 그럼 추가하지 않는다
- 한 번만 쓰는 기능인데 40KB를 로드하는가 → 비용이 맞지 않는다

**불필요한 의존성을 막는 것이 이 스킬의 주 목적이다.** 승인 요청은 그다음이다.

## 2. 사용자에게 물을 때 담을 내용

절대 "○○ 써도 될까요?"만 묻지 않는다. 판단에 필요한 정보를 준다:

1. **무엇을** — 라이브러리명, 버전, 용량(gzip 기준)
2. **왜** — 이게 없으면 어떤 기능이 안 되는지 구체적으로
3. **대안** — 직접 구현 시 예상 작업량, 다른 라이브러리와의 비교
4. **비용** — 로딩 시간, 유지보수, CDN 의존
5. **범위** — 어느 페이지에서만 로드되는지 (전 페이지 로드면 비용이 커진다)

## 3. 승인 조건

- **CDN으로 `<script>` 한 줄**로 끝나야 한다. 빌드 단계가 필요하면 이 프로젝트에 맞지 않는다
- 버전을 고정한다. `@latest` 금지
- 특정 페이지에서만 필요하면 그 페이지에서만 로드한다

## 4. 승인 후 처리 (전부 해야 완료다)

```
1. 해당 HTML에 <script defer src="...고정버전..."> 추가
2. js/config.js 의 CDN 버전 상수에 등재
3. CLAUDE.md 의 "승인된 의존성" 목록 갱신
4. .claude/skills/blog-spec/SKILL.md 의 허용 CDN 표 갱신
5. .claude/skills/dep-request/SKILL.md (이 파일) 의 승인 목록 갱신
6. .claude/agents/*.md 의 허용 라이브러리 문구 갱신
```
**문서 갱신을 빠뜨리면 다음 라운드에 에이전트가 "승인 안 된 라이브러리"라며 걷어낸다.**

## 5. 거절된 경우

대안을 직접 구현하는 계획을 세운다. 사용자를 설득하려 다시 조르지 않는다.
